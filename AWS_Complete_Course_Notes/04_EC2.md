# 04. EC2 Deep Dive & Storage: EBS, EFS, and FSx

This guide provides an exhaustive deep dive into **Amazon EC2 (Elastic Compute Cloud)** and the storage options available: **EBS**, **EFS**, and **FSx**. 

---

## 1. Amazon EC2 Overview
Amazon EC2 is a web service that provides secure, resizable compute capacity in the cloud. It represents Infrastructure as a Service (IaaS). You launch virtual servers (called **instances**), manage storage, and configure networking and security.

### EC2 Instance Naming Convention
AWS names EC2 instances using a system like `t3.large` or `m5.2xlarge`. Here is how to decode it:
*   **t** (Instance Family): Tells you what the instance is optimized for (e.g., General Purpose, Compute, Memory).
*   **3** (Generation Number): The hardware generation (higher is newer and faster).
*   **large** (Instance Size): Determines the number of vCPUs, RAM, network bandwidth, and cost. Double the size (e.g., `xlarge` to `2xlarge`) usually doubles the capacity and cost.

### EC2 Families Cheat Sheet
*   **General Purpose (T, M):** Balanced compute, memory, and networking. Ideal for web servers, dev environments.
*   **Compute Optimized (C):** High-performance processors. Ideal for batch processing, media encoding, scientific modeling.
*   **Memory Optimized (R, X):** Designed for fast performance for workloads that process large datasets in memory. Ideal for high-performance databases (RDS, MongoDB) and in-memory caches (ElastiCache Redis).
*   **Accelerated Computing (G, P):** Use hardware accelerators (GPUs). Ideal for Machine Learning training, 3D rendering, and video processing.
*   **Storage Optimized (I, D, H):** Designed for workloads that require high, sequential read and write access to very large datasets on local storage. Ideal for NoSQL databases, data warehousing.

## 2. EC2 Purchasing Options
AWS offers multiple ways to pay for EC2 instances, depending on your budget and workload flexibility.

| Option | Pricing | Best Use Case |
| :--- | :--- | :--- |
| **On-Demand** | Fixed rate by the second or hour. No commitment. | Short-term, unpredictable workloads. Dev/Testing. |
| **Savings Plans** | Up to 72% discount. Commit to a consistent amount of compute usage (e.g., $10/hour) for 1 or 3 years. | Long-term workloads with flexible instance types/regions. |
| **Reserved Instances (RI)** | Up to 72% discount. Commit to a specific instance configuration (type, region) for 1 or 3 years. | Steady-state workloads (e.g., core database servers). Can be *Standard* (fixed) or *Convertible* (change type). |
| **Spot Instances** | Up to 90% discount. AWS sells spare capacity. However, AWS can terminate them with a **2-minute warning** if they need the capacity back. | Batch jobs, image processing, stateless apps, CI/CD runners. |
| **Dedicated Hosts** | Physical servers fully dedicated to your use. Very expensive. | Strict licensing models (Bring Your Own License - BYOL) or regulatory compliance. |
| **Dedicated Instances** | Instances run on hardware dedicated to a single customer, but other instances on the same host can belong to your other accounts. | Compliance requirements. |

## 3. Instance Metadata Service (IMDS)
EC2 instances can query their own details (such as public IP, instance ID, security groups) using the **Instance Metadata Service (IMDS)** via a local non-routable IP: `http://169.254.169.254`.

### IMDSv1 vs IMDSv2
*   **IMDSv1:** Uses a simple HTTP GET request. Unsecured and vulnerable to SSRF (Server-Side Request Forgery) attacks.
*   **IMDSv2:** Requred by modern security audits. Uses session-oriented requests. You must first fetch a token via a PUT request, then send that token in the GET request.

#### How to query metadata using IMDSv2 (Bash commands):
```bash
# Step 1: Get the session token (valid for 6 hours / 21600 seconds)
TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")

# Step 2: Request the instance ID using the token
curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id

# Step 3: Request the public IP address
curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/public-ipv4
```

## 4. User Data Scripts
**User Data** allows you to automate tasks when an instance starts for the first time (bootstrapping). It runs as the `root` user.

### Practical User Data Bash Script (Installs Apache and hosts a webpage showing Instance ID)
When launching an EC2 instance, paste this code in the Advanced Details -> User Data field:

```bash
#!/bin/bash
# 1. Update package manager
yum update -y

# 2. Install Apache Web Server
yum install -y httpd

# 3. Start Apache and enable it to run on boot
systemctl start httpd
systemctl enable httpd

# 4. Fetch the Instance ID using IMDSv2
TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
INSTANCE_ID=$(curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id)

# 5. Create a dynamic HTML landing page
echo "<h1>Hello from Antigravity AWS Course!</h1>" > /var/web/index.html
echo "<p>This page is running on EC2 Instance: <strong>$INSTANCE_ID</strong></p>" >> /var/www/html/index.html
```

## 5. Security Groups (Stateful Firewalls)
*   A **Security Group** acts as a virtual firewall that controls inbound and outbound traffic for your EC2 instances.
*   **Rule Configuration:** You write rules specifying permitted protocols (TCP, UDP, ICMP), port ranges (e.g., 22 for SSH, 80 for HTTP), and sources (IP addresses or other Security Groups).
*   **Stateful Nature:** Security Groups are **stateful**. This means if you allow inbound traffic on port 80 (HTTP) from the internet, the returning outbound traffic is automatically allowed, regardless of outbound rules.

## 6. EC2 Storage Options: Instance Store vs. EBS

When attaching storage to an EC2 instance, you have two core block-level choices:

### 1. EC2 Instance Store (Ephemeral)
*   **What it is:** Physical SSD disks physically attached to the host server hardware.
*   **Performance:** Extreme high speed, low latency, high IOPS.
*   **Data Loss:** Data is **lost** when the instance is **Stopped** or **Terminated**. Data survives a reboot.
*   **Use Case:** Cache drives, temp files, swap space.

### 2. Amazon Elastic Block Store (EBS)
*   **What it is:** A network-attached drive. Think of it as a virtual USB flash drive that you plug into your instance.
*   **Data Loss:** Data **survives** when the instance is stopped. It behaves like a persistent hard disk.
*   **Limitation:** A standard EBS volume can only be attached to **one EC2 instance at a time** in the same Availability Zone.

## 7. EBS Volume Types

AWS offers SSD-backed and HDD-backed volumes:

### SSD-Backed Volumes (For transactional workloads, databases, boot volumes)
1.  **General Purpose SSD (gp2 / gp3):**
    *   *gp3:* The default choice. You can customize IOPS (Input/Output Operations Per Second) and throughput independently of volume size.
    *   *gp2:* Older generation. IOPS scales with size.
    *   *Use Case:* Boot volumes, development databases, general workloads.
2.  **Provisioned IOPS SSD (io1 / io2 Block Express):**
    *   Designed for sub-millisecond latency and extreme performance.
    *   *Feature:* Supports **EBS Multi-Attach** (attach one EBS volume to up to 16 Nitro-based EC2 instances simultaneously).
    *   *Use Case:* Massive relational databases (Oracle, SAP HANA).

### HDD-Backed Volumes (For throughput-heavy workloads, big data, logging)
1.  **Throughput Optimized HDD (st1):**
    *   Low cost, high throughput.
    *   *Use Case:* Big data, MapReduce, data warehousing, log processing. Cannot be used as a boot volume.
2.  **Cold HDD (sc1):**
    *   The lowest-cost volume type for infrequently accessed data.
    *   *Use Case:* Archive storage.

## 8. Amazon EFS (Elastic File System)
While EBS is a block-level storage for a single instance, **Amazon EFS** is a managed **network file system (NFS)** that can be shared across **hundreds of EC2 instances simultaneously** across multiple Availability Zones.

*   **Operating System:** Works only with **Linux** instances.
*   **Scalability:** Grows and shrinks automatically as you add or remove files. You only pay for what you use.
*   **Protocols:** Uses the NFSv4 protocol.
*   **Storage Classes:** 
    *   *Standard:* For active data.
    *   *Infrequent Access (IA):* For files not read daily. EFS Lifecycle Management moves files to IA automatically after a set number of days (e.g., 30 days) to save up to 92% of costs.

## 9. Amazon FSx (Fully Managed Specialized File Systems)
EFS is Linux-only. If you need specialized third-party file systems, AWS offers **Amazon FSx**:

1.  **FSx for Windows File Server:**
    *   A fully managed native Windows file system (SMB protocol).
    *   *Features:* Integrates natively with Microsoft Active Directory, Windows ACLs, and distributed file systems.
    *   *Use Case:* Windows application sharing, home directories, Microsoft SQL Server.
2.  **FSx for Lustre:**
    *   A high-performance file system designed for parallel processing of massive datasets.
    *   *Features:* Natively integrates with Amazon S3. It can load data from S3, run massive computations on EC2, and save output back to S3.
    *   *Use Case:* High-Performance Computing (HPC), Machine Learning training, financial modeling, video rendering.
3.  **FSx for NetApp ONTAP & OpenZFS:**
    *   Allows migration of on-premises NetApp or ZFS storage architectures to AWS without rewriting applications.



## 10. Interactive Hands-On Lab: Deploying EC2 Instances

Learn how to configure, launch, and terminate compute nodes programmatically.

### A. AWS CLI v2 Commands
```bash
# 1. Create a Security Group for Web Access
aws ec2 create-security-group \
    --group-name web-security-group \
    --description "Allow HTTP and SSH access" \
    --vpc-id vpc-12345678

# 2. Authorize Inbound Rules (HTTP Port 80 and SSH Port 22)
aws ec2 authorize-security-group-ingress \
    --group-name web-security-group \
    --protocol tcp --port 80 --cidr 0.0.0.0/0

aws ec2 authorize-security-group-ingress \
    --group-name web-security-group \
    --protocol tcp --port 22 --cidr 203.0.113.0/24

# 3. Launch a t3.micro EC2 Instance using an Amazon Linux 2 AMI
aws ec2 run-instances \
    --image-id ami-0c55b159cbfafe1f0 \
    --count 1 \
    --instance-type t3.micro \
    --key-name ProductionKeyPair \
    --security-groups web-security-group \
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=WebServer-Cli}]'

# 4. Terminate an Instance
aws ec2 terminate-instances --instance-ids i-0123456789abcdef0
```

### B. Python Boto3 SDK Implementation
```python
import boto3
from botocore.exceptions import ClientError

ec2_resource = boto3.resource('ec2', region_name='us-east-1')
ec2_client = boto3.client('ec2', region_name='us-east-1')

def launch_web_server():
    try:
        print("Launching EC2 instance...")
        instances = ec2_resource.create_instances(
            ImageId='ami-0c55b159cbfafe1f0', # Replace with valid AMI ID
            MinCount=1,
            MaxCount=1,
            InstanceType='t3.micro',
            KeyName='ProductionKeyPair',
            TagSpecifications=[
                {
                    'ResourceType': 'instance',
                    'Tags': [{'Key': 'Name', 'Value': 'Boto3-Webserver'}]
                }
            ]
        )
        instance = instances[0]
        print(f"Waiting for instance {instance.id} to run...")
        instance.wait_until_running()
        instance.reload()
        print(f"Instance is running. Public IP: {instance.public_ip_address}")
        return instance.id
    except ClientError as e:
        print("Failed to run instance:", e)

if __name__ == '__main__':
    launch_web_server()
```

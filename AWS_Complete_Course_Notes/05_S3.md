# 05. Amazon S3 Complete Guide: Storage Classes, Lifecycle Policies, and Security

**Amazon Simple Storage Service (S3)** is an object storage service offering industry-leading scalability, data availability, security, and performance. 

---

## 1. Amazon S3 Core Concepts
Unlike block storage (like EBS) which writes bytes directly to sectors on a drive, S3 is **Object Storage**. This means files are stored as complete units (objects) inside containers called **Buckets**.

*   **Buckets:** 
    *   Buckets are the top-level folders in S3. 
    *   Bucket names must be **globally unique** across all AWS accounts in the world.
    *   Bucket names must be lowercase, between 3 and 63 characters long, and contain no spaces or underscores.
*   **Objects:**
    *   An object is a file and any metadata that describes that file.
    *   Max Object Size: **5 Terabytes** (5 TB).
    *   If you upload a file larger than 5 Gigabytes (5 GB), you *must* use **Multipart Upload** (which splits the file and uploads blocks in parallel). It is recommended for files over 100 Megabytes.
*   **Keys:**
    *   The "Key" is the full path of the object inside the bucket.
    *   *Example:* If your bucket is `my-company-photos` and your file path is `2026/june/logo.png`, then the Key is `2026/june/logo.png`.
    *   *Flat Structure:* S3 does not have actual folders. The `/` character in keys is just a naming convention. The system is a flat key-value store.

## 2. S3 Storage Classes

To optimize costs, AWS offers seven different storage classes based on access frequency and data durability. All classes (except One Zone-IA) feature **99.999999999% (11 9s) of durability**, meaning AWS replicates your files across at least three distinct Availability Zones.

| Storage Class | Durability | Availability | Min Storage Duration | Retrieval Fees | Best Use Case |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **S3 Standard** | 11 9s | 99.99% | None | None | Active, frequently accessed data (web assets, app data). |
| **S3 Intelligent-Tiering** | 11 9s | 99.9% | None | None | Data with unknown or changing access patterns. Moves data automatically between Frequent and Infrequent tiers. |
| **S3 Standard-IA** | 11 9s | 99.9% | 30 Days | Per GB retrieved | Data accessed infrequently but needs millisecond access when requested (backups, disaster recovery). |
| **S3 One Zone-IA** | 11 9s (in 1 AZ) | 99.5% | 30 Days | Per GB retrieved | Secondary backup files that can be easily recreated if the AZ is destroyed. |
| **S3 Glacier Instant** | 11 9s | 99.9% | 90 Days | Per GB retrieved | Archived data accessed once/twice a year, but requires millisecond retrieval. |
| **S3 Glacier Flexible** | 11 9s | 99.99% | 90 Days | Per GB retrieved | Archives. Retrieval times: Expedited (1-5 mins), Standard (3-5 hours), Bulk (5-12 hours). |
| **S3 Glacier Deep Archive**| 11 9s | 99.99% | 180 Days | Per GB retrieved | Long-term compliance archives. Retrieval times: Standard (12 hours), Bulk (48 hours). Cheapest storage tier. |

## 3. S3 Lifecycle Policies (With JSON Example)
Instead of manually moving files to cheaper storage classes, you configure **Lifecycle Policies** to automate transitions.

*   **Transition Actions:** Define when objects should migrate to another storage class (e.g., move from Standard to Standard-IA after 30 days, then to Glacier Deep Archive after 90 days).
*   **Expiration Actions:** Define when objects should be deleted permanently (e.g., delete log files after 365 days).

### Example JSON Lifecycle Policy
This policy configuration automatically shifts objects in the `/logs/` prefix to Glacier after 30 days and deletes them completely after 90 days.

```json
{
  "Rules": [
    {
      "ID": "ArchiveAndDeleteLogs",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "logs/"
      },
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "GLACIER"
        }
      ],
      "Expiration": {
        "Days": 90
      }
    }
  ]
}
```

## 4. Amazon S3 Security & Encryption

AWS offers multiple ways to restrict access and encrypt S3 data.

### S3 Encryption Methods (At Rest)
1.  **SSE-S3 (Server-Side Encryption with S3-Managed Keys):**
    *   The default option. AWS handles the encryption keys automatically using AES-256.
2.  **SSE-KMS (Server-Side Encryption with AWS Key Management Service):**
    *   Allows you to manage your own keys in AWS KMS. Provides an audit trail of who used the key to decrypt files.
3.  **SSE-C (Server-Side Encryption with Customer-Provided Keys):**
    *   You supply your own encryption key in the header of the API request. AWS encrypts the file but does not store the key. If you lose the key, your data is gone forever.
4.  **Client-Side Encryption:**
    *   You encrypt the files on your own computer/server before uploading them to S3. AWS only sees encrypted bytes.

### Restricting Access: S3 Bucket Policies
An S3 Bucket Policy is a resource-based JSON policy attached directly to the bucket.

#### Example S3 Bucket Policy: Block all non-HTTPS Traffic
This policy explicitly denies any request to read or write data in `my-secure-bucket-101` if the connection is not secured via SSL/TLS (HTTPS).

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EnforceHTTPSOnly",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::my-secure-bucket-101",
        "arn:aws:s3:::my-secure-bucket-101/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

## 5. S3 Replication (CRR & SRR)
You can set S3 to automatically copy new objects to another bucket for disaster recovery or geographic compliance.
*   **Cross-Region Replication (CRR):** Copies objects to a bucket in a *different* AWS Region (e.g., duplicate `us-east-1` bucket to `eu-west-1` for European compliance).
*   **Same-Region Replication (SRR):** Copies objects to another bucket in the *same* Region (e.g., copy logs to a master audit bucket).
*   *Requirement:* **S3 Versioning must be enabled** on both the source and destination buckets.

## 6. Advanced S3 Features

### 1. S3 Versioning & MFA Delete
*   **Versioning:** Keeps multiple versions of an object in the same bucket. If you upload a file with the same name, the old file becomes a "non-current version" rather than being overwritten. This protects against accidental deletes.
*   **MFA Delete:** Requires a physical MFA token code to permanently delete an object version or disable versioning on the bucket.

### 2. S3 Object Lock (WORM - Write Once, Read Many)
Used to satisfy regulatory requirements where files must not be deleted or modified for a specific time.
*   **Compliance Mode:** No one, not even the root user of the account, can delete the files or change the retention period until the lock expires.
*   **Governance Mode:** Special users with specific IAM permissions (like `s3:BypassGovernanceRetention`) can override the locks.
*   **Legal Hold:** A simple on/off switch that locks files indefinitely until explicitly turned off (does not use a timer).

### 3. S3 Select & Glacier Select
*   By default, if you have a 5 GB CSV file in S3 and only want to read 2 lines, you have to download the entire 5 GB file.
*   **S3 Select** allows you to use standard SQL queries (e.g., `SELECT * FROM s3object s WHERE s.age > 30`) to retrieve only the subset of data you need. 
*   This reduces data transfer costs and accelerates application query speeds.

### 4. S3 Transfer Acceleration
*   Speeds up file uploads to S3 by routing traffic through the nearest AWS **Edge Location**.
*   Traffic travels from the Edge Location to your S3 bucket over the private, high-speed AWS Global Network, bypassing public internet congestion.



## 10. Interactive Hands-On Lab: Working with S3 Buckets

Learn how to configure versioning, upload objects, and block public access.

### A. AWS CLI v2 Operations
```bash
# 1. Create a secure private bucket
aws s3api create-bucket --bucket production-data-vault-999 --region us-east-1

# 2. Enable Bucket Versioning
aws s3api put-bucket-versioning \
    --bucket production-data-vault-999 \
    --versioning-configuration Status=Enabled

# 3. Upload a file with Server-Side Encryption (AES256)
aws s3 cp document.pdf s3://production-data-vault-999/document.pdf --sse AES256

# 4. Configure Public Access Block (Security Hardening)
aws s3api put-public-access-block \
    --bucket production-data-vault-999 \
    --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"
```

### B. Python Boto3 SDK Script
```python
import boto3
from botocore.exceptions import ClientError

s3_client = boto3.client('s3')

def manage_s3_bucket(bucket_name, file_path, object_name):
    try:
        # Create bucket
        print(f"Creating bucket: {bucket_name}...")
        s3_client.create_bucket(Bucket=bucket_name)
        
        # Upload object
        print(f"Uploading file {file_path} as {object_name}...")
        s3_client.upload_file(
            file_path, 
            bucket_name, 
            object_name,
            ExtraArgs={'ServerSideEncryption': 'AES256'}
        )
        print("Upload completed securely!")
        
    except ClientError as e:
        print("S3 Operations Error:", e)

if __name__ == '__main__':
    manage_s3_bucket('boto3-vault-enterprise-01', 'local_report.txt', 'reports/january.txt')
```
